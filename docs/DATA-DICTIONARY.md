# قاموس البيانات

يحوّل PharmaDash جميع ملفات Excel وCSV وPDF إلى النموذج التالي قبل الحساب:

| الحقل | الوصف | مطلوب للحساب |
|---|---|---|
| `doctor` | اسم الطبيب | الطبيب أو الدواء؛ يفضّل وجوده |
| `service` | اسم الدواء/الخدمة | الطبيب أو الدواء؛ يفضّل وجوده |
| `section` | التخصص/القسم | اختياري، مطلوب لتحليل التخصص |
| `patient` | رقم المريض | اختياري، مطلوب لحساب المرضى الفريدين |
| `patientName` | اسم المريض | اختياري وحساس |
| `orderNo` | رقم الطلب | اختياري وحساس |
| `status` | حالة الطلب | اختياري؛ يُوحّد إلى Closed/Canceled/New/Opened/Pending/Active |

تقبل رؤوس الأعمدة الشائعة بالعربية والإنجليزية، مثل `Doctor Name`/`اسم الطبيب` و`Service Name`/`اسم الخدمة`.

## قواعد الحساب

- توحّد المسافات، Unicode، اختلافات الألف/الياء، وحالة الأحرف عند بناء المفاتيح.
- يبقى أول اسم مقروء هو اسم العرض؛ المفتاح الموحّد فقط يمنع تكرار الكيان.
- هوية المريض المجمعة هي `الفرع + رقم المريض` لأن أرقام المرضى قد تتكرر بين أنظمة الفروع.
- لا تُحذف الصفوف المكررة تلقائيًا؛ تعرضها لوحة الجودة ويمكن حذف التكرار التام بموافقة المستخدم.
- يختار العرض الرئيسي أحدث فترة زمنيًا من اسم الشهر/السنة، وليس آخر عنصر في المصفوفة.

## PDF

يدعم القارئ ملفات PDF النصية ذات أعمدة Patient No وPatient Name وService Name وOrder No وStatus وDoctor Name/Section، أو مقابلاتها العربية. يكتشف مواضع الأعمدة من الرأس حتى إذا قُسّم العنوان إلى أكثر من جزء، ويجمع أسطر السجل الملفوفة القريبة. يدعم أرقام المرضى اللاتينية والعربية-الهندية والحروف والشرطات.

ملفات PDF المصورة لا تحتوي نصًا يستطيع PDF.js قراءته؛ يجب تشغيل OCR أو تصدير تقرير PDF نصي من النظام المصدر أولًا.

تخطيط Oracle الثابت متاح كاحتياط، ويظهر تنبيه جودة عند استخدامه. يجب مراجعة عينة من الصفوف لأن اختلاف تصميم التقرير قد ينقل النص إلى عمود غير صحيح.

## التصدير المجهول

يستخدم التصدير المجهول قائمة حقول مسموح بها فقط. يحتفظ بالطبيب والدواء والتخصص والحالة، ويفرغ رقم المريض واسم المريض ورقم الطلب، ويحذف أي أعمدة مصدر إضافية غير معروفة مثل رقم الهوية أو الهاتف. تُستبدل أسماء الملفات والفترات غير المؤرخة بعناوين عامة.
